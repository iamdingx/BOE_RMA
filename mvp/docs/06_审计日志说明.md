# 审计日志说明（audit_log）

## 1. 设计原则

1. **只增不删**：应用层无任何删除接口；MySQL 侧 `trg_al_no_delete` 触发器阻断 DELETE。
2. **全关键动作留痕**（M-14）：受控修正、还货方式变更、RETAINED 处置、BUFFER 跨 PN 替代审批、报废审批、RMA 关闭、差异审批/驳回、质检判定、出库发运、封箱、照片上传、登录、状态流转。
3. **可追溯**：`biz_type + biz_no` 定位业务对象，`field/old_value/new_value` 记录变更前后值，`reason` 记录原因，`operator/approved_by` 记录操作人与同意人。
4. **事务内写入**：与业务变更同事务，业务回滚则审计一并回滚，杜绝"改了没记"。

## 2. 表结构

| 字段 | 说明 |
|---|---|
| log_id | 自增主键 |
| tenant_id | 租户 |
| biz_type | 业务类型（sn_item / forecast_order / discrepancy_record / outbound_order / box_info / shipment_box / buffer_stock / buffer_substitute_approval / photo_evidence / sys_user） |
| biz_no | 业务单号或 SN |
| action | 动作（见下表） |
| field / old_value / new_value | 变更字段与前后值 |
| reason | 原因（受控修正/驳回原因/审批意见等） |
| operator | 操作人 |
| approved_by | 同意人（项目人员） |
| created_at | 时间 |

## 3. 动作字典

| action | 触发场景 | 对应需求 |
|---|---|---|
| STATUS_TRANSITION | 任意 SN/RMA 状态跃迁 | 4.2 / 4.2-B |
| CONTROLLED_CORRECTION | 受控修正、允收登记、调拨清点确认 | KT-05 / RC-03 |
| INSPECTION_JUDGE | 质检判定录入 | IN-01 |
| DISCREPANCY_APPROVE | 差异审批通过 | DC-04 |
| DISCREPANCY_REJECT | 差异驳回（含解锁） | DC-04 / RK-11 |
| SCRAP_APPROVAL | 报废出库审批通过/驳回 | OB-03 / L-08 |
| BUFFER_SUBSTITUTE_APPROVAL | 跨 PN 替代审批 | BS-08 |
| RETAINED_DISPOSE | RETAINED 原片处置（含备件报废） | RT-09 / BS-09 |
| OUTBOUND_SHIP | 出库发运 | OB-06 / OB-09 |
| BOX_SEAL | 收货箱/发货箱封箱 | KT-08 / OB-08 |
| PHOTO_UPLOAD | 照片上传 | PH-04 |
| RMA_CLOSE | RMA 自动关闭 | RT-05 / M-01 |
| LOGIN | 登录 | — |

## 4. 查询

- 接口：`GET /api/v1/audit-logs?action=&biz_no=&page=&size=`（项目人员 / 系统管理员）
- SN 维度全轨迹：`GET /api/v1/sn/{sn}/trace` 返回 `sn_item + rounds + discrepancies + inspections + returns + photos + audit`

## 5. 留存与合规

- 审计日志与业务记录同库，不设过期；建议按年度归档到冷存储（二期）。
- 照片 `photo_evidence.retention_until = uploaded_at + 2 年`，到期仅统计提示（`PurgeExpiredPhotos`），**不自动删除**（PH-03）。
- 双异常记录（FORECAST_ANOMALY / ARRIVAL_ANOMALY）永久保留，触发器阻断删除（DC-05）。
